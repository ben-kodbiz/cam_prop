# AGENTS.md

Guidance for AI agents (and humans) working in this repository.
The full product spec is `agentodo.md` — read it before making design
decisions. The methodology in force is `METHODOLOGY.md`.

## Non-negotiable rules

- **No predetermined conclusions** about any side of any conflict. The system
  evaluates individual claims against evidence.
- **No source → no factual assertion.** Never invent evidence, statistics,
  quotations or citations.
- **`unknown` and `insufficient_evidence` are legitimate outcomes.** If
  evidence is insufficient, mark unknown. If sources disagree, mark disputed.
- **High-impact topics always require human review** before publication;
  never auto-publish them. High-impact topics are listed in
  `app/constants.py:HIGH_IMPACT_TOPICS`.
- **Never conflate legal record types** (allegation / provisional measure /
  judgment / …); every legal record must state what it does *not* establish.
- **Copyright:** store short excerpts (≤ 500 chars), page/section pointers,
  URLs and hashes — never mirror third-party content.
- Never commit secrets. Use `.env` (see `.env.example`).

## Commands

```bash
pip install -e ".[dev]"   # setup (also: pip install -e ".[pdf]" for PyMuPDF)

pytest                    # tests
ruff check .              # lint
ruff format .             # format (CI runs --check)
mypy                      # typecheck (configured via pyproject; no args needed)

python -m app init-db     # create data/evidence.db from data/schema.sql
python -m app seed        # load fixture data (everything is marked "SEED")
python -m app export      # write data/generated/*.json and web/data/*.json
python -m app queue       # pending review queue
python -m app review --subject-type claim --subject-id CLM-… --reviewer NAME \
           --decision approve|reject|request [--approve-high-impact] [--notes …]
python -m app assess [--claim-id CLM-…]   # deterministic provisional assessment
python -m app stats
python -m app backup [--out PATH]
scripts/backup.sh [dest_dir]              # DB + generated data + archive + manifest
python -m http.server --directory web 8000  # serve the static site
```

Run a single test file: `pytest tests/test_claims.py`; single test:
`pytest tests/test_claims.py::test_status_requires_evidence`.

## Architecture

- `data/schema.sql` is the single source of truth for the database (14 tables
  + `claims_fts` FTS5). `app/db.py:init_db` executes it; tests rely on this —
  don't create tables ad hoc in code.
- Pipeline: ingestion → sources (hashed, archived) → claims → evidence →
  deterministic provisional assessment (`agents/evidence_agent.py`) → human
  review (`app/review.py`) → export (`app/export.py`) → static site (`web/`).
- IDs are `PREFIX-YYYY-NNNN` (e.g. `CLM-2026-0007`), generated by
  `app/util.py:next_id`.
- The public site is **static**: `web/` is HTML/CSS/vanilla JS loading JSON
  from `web/data/`. Do not add React/Tailwind or a backend server for the
  public site. FastAPI is optional for local development only.
- All mutations should go through `app/` functions (not raw SQL) so the audit
  log is written. `app/audit.py` is append-only; never update audit rows.

## Enforced invariants (do not weaken)

- A claim cannot become `supported` without ≥ 1 linked evidence with
  relationship `supports`; cannot become `contradicted` without `contradicts`
  evidence (`app/claims.py:set_status` + `STATUS_EVIDENCE_REQUIREMENTS`).
- Claim status cannot change while `review_status != 'approved'` (unless a
  human `override=True`).
- Publishing (`app/review.py:record_publication`, `publishing/`) requires
  `review_status == 'approved'`.
- Source registration deduplicates by canonical URL
  (`app/util.py:canonicalize_url` strips tracking params, `www`, fragments).
- Claim creation deduplicates by normalized text
  (`app/util.py:normalize_claim_text`).
- Evidence `excerpt` length ≤ 500 chars.

## Conventions

- Python 3.11+ stdlib-first; new deps must justify themselves.
- Frontend: no frameworks. Keep the site static-first and semantic.
- Tests are mandatory for new claim/evidence/review code paths — mirror the
  existing suites in `tests/`.
- Phase 1 has **no LLM anywhere**; when adding one, use a local
  OpenAI-compatible endpoint configured via `.env` (`OE_LLM_*`), never a
  hard-coded provider or key. RAG is SQLite FTS5 only for now (no vectors).
- Seed data must be clearly marked `SEED` — it exercises the pipeline, it
  never makes real-world assertions.

## Phasing

Build incrementally (spec §57): repository → schema → ingestion → claims →
evidence → review → static site → tests → LLM → law module → corporate →
alternatives → publishing → analytics. Phase 1 is complete; LLM integration
is Phase 3. Do not attempt the whole system in one pass.
